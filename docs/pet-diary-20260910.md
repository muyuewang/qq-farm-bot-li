# 萌宠成长日记适配与本地验证（2026-09-10）

接入活动目录、比熊之家、爪印手记、拾物小铺、节令小礼、宝藏护送和游戏商城的活动商品筛选。本文记录上游活动分支的实现、协议来源与本地验证范围。

## 协议与资源来源

- 协议依据活动真实抓包及官方小程序 encoder / decoder；用于回归的消息体与预期字段保存在 `core/tests/fixtures/pet-*.json`。
- 当前 QQ 小程序 `1.14.0.1`，实际登录版本 `1.14.0.1_20260909`。
- 活动分组 `2026090100`，主活动 `2026090101`，种子赠礼 `2026090102`，拾物小铺 `2026090103`。
- `core/src/proto/pet-diary.proto` 按官方 encoder / decoder 的字段号、类型及嵌套消息实现。真实请求与编码结果逐字节一致，真实响应的全部已定义字段与官方 decoder 逐项比较；未使用响应字节数推断含义。
- 活动图像位于 `web/public/activity-assets/pet-diary/`。`core/src/activity-data/pet-diary-assets.json` 记录 132 项正式资源的原始路径、官方 CDN URL、SHA-256；图集资源另记录矩形、旋转和原始尺寸，Spine 合成图另记录骨骼、图集和贴图的来源与哈希、动作、取帧时间、裁切和布局参数。所有记录与本地文件的 SHA-256 匹配。
- 手记页采用官方纸纹背景、山景和拿相机的比熊、原始横幅、照片、照片下方图案、图钉、空白照片和底部栏目图标。横幅文字直接来自原图：“多跟比熊互动可以解锁更多照片哦~”，右侧比熊图案一并保留。页内原先自拟的装饰文案已移除。
- 手记原图是纵向图片；已按原图比例固定相框，并明确限制图片尺寸，修复图片被网格固有高度撑大后裁掉下半部分的问题。

## 活动界面与本地 Spine 合成

- 官方白露、小铺、手记、幼犬和成年比熊的骨骼版本均为 **Spine 3.8.99**。本地使用 `pixi.js 7.4.3` 和 `@pixi-spine/runtime-3.8 4.0.6` 按骨骼、mesh 和遮罩正确渲染。白露图集的矩形范围含其他网格的零件，直接裁矩形会出现头、身体散开的问题，已换成完整渲染结果。
- 四板块保留五张 PNG：`scene-home-puppy.png`、`scene-home-adult.png`、`scene-stories.png`、`scene-shop.png`、`scene-bailu.png`。家中场景将官方房间和 `idle` 动作合成；其余使用 `loop` 动作，均取第 0.7 秒。文字、成长进度和业务按钮仍独立渲染。
- 手记、小铺顶部接入高清 WebP 动图：`scene-stories.webp`（2040×920，1025028 字节）、`scene-shop.webp`（2040×900，712616 字节），完整循环均为 3 秒。使用官方 `loop` 骨骼按 12fps 导出 RGBA PNG 帧，再由 `img2webp 1.6.0` 直接编码，避免 GIF 调色板中转损失清晰度；官方分段关键帧的节奏保持不变，重复帧由编码器合并。高清静态 PNG 同步更新，动图 URL 带 `?v=20260910-hd`。`prefers-reduced-motion: reduce` 自动回退到 PNG，不支持 WebP 时也显示 PNG。
- 挂牌保留原图自带的棕色笔刷底纹，“幼年期 / 成年期”文字按底纹位置排布，避免额外背景遮住底图。幼年采用官方 `img_pet_rarity2` 蓝色底图及“稀有”，成年采用 `img_pet_rarity4` 金色底图及“天工”，与官方客户端按宠物配置切换品质的行为一致。
- `.pet-diary` 内正文独立滚动，活动底栏在滚动区之外，图标限制在导航行内；切换栏目后回到顶部。永久比熊领取状态放在详情区，避免挤占投喂按钮周围空间。共享布局组件未改，外层样式仅在 `.page-scroll` 直接挂载该活动时生效。
- 小铺点击商品先打开兑换弹窗，展示数量、总成本、余额和剩余限购，只有点击明确的“兑换”按钮才提交；手记继续使用独立领奖按钮。
- 白露正式页面接入 `scene-bailu.webp`：900×1604、80 帧、完整循环约 6.67 秒。按官方 Spine `loop` 动作导出 PNG 帧后直接编码 WebP，保持现有裁切和人物位置。成品约 7.53 MB，仅打开对应栏目时加载；减少动态效果或不支持 WebP 时回退到原 PNG。低分辨率 GIF 预览、骨骼和导出工具仅保留本地。
- **不上传合成输入和工具**：Spine 原始 `.skel`、骨骼 JSON、`.atlas`、整张图集和导出依赖均放在 `output/`；该目录及 `.playwright-cli/` 已加入 `.gitignore`。旧的 14 张手工拼层切片也移回本地目录。生产依赖未新增 Pixi、Spine 或 GIF 编码器，正式资源目录没有骨骼和图集配置文件。

五张成品图的复现参数保留在正式资源清单中；导出脚本和本地服务器保留在忽略目录 `output/pet-spine/`，不随应用发布。

## 操作一致性与资源限制

- 一键务农确认文案简化为“确定要一键务农吗？”，移除随活动变化而过时的固定清理项目列表。
- 活动操作共用串行写入队列，执行前重新查询活动状态和库存，检查每日次数、领取状态、限购和成本；成本按同币种合并后验证。
- 活动兑换拒绝钻石成本和钻石替代成本。锦囊付费刷新在串行操作内重新核对次数和点券库存，余额未知、点券不足、达到上限、尚未完成选择时均不发送付费请求。面板提交明确的免费/点券意图及预期付费次数，旧免费点击不会升级为收费，旧付费次数不能重复使用；拒绝钻石覆盖参数。官方命令 41 的请求体仍为空，面板前置校验参数不会发给游戏服务端；协议不提供币种锁，无法阻止其他客户端并发消费导致的服务端币种变化。
- 操作成功但随后刷新失败时，明确返回成功与刷新失败信息，前端暂停继续消耗，避免误重试。账号切换会清空详情，并丢弃旧账号尚未返回的结果。
- 萌宠查询与操作的 worker 超时已按串行 RPC 调整，避免被原先 10 秒 IPC 超时提前截断。
- 比熊成年后的永久宠物目录已加入 `90031`、官方头像、活动获得方式和技能“比熊润田”。服务端尚未返回该宠物时，宠物页仍显示“未获得”；拥有、上场状态仅由真实宠物响应决定，活动成年不会自行伪造已拥有状态。
